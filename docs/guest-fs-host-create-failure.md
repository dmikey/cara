# Guest file creation: host open failure

The Android crash reported on 2026-11-25 symbolicated to `IOFile::Resize` from `FS_USER::CreateFile`. Both the save-data and SDMC archive implementations previously created an `IOFile` and immediately called its handler's `Resize` without checking whether the host open succeeded. Their zero-byte branch also ignored `CreateEmptyFile` failure and returned successful creation.

The portable correction checks host acquisition before either operation. The handle wrapper also rejects closed, default, failed and moved-from operations without dereferencing a null handler. The host open errno is captured before replacing or destroying the old handler; it is not part of the save-state serialization. An explicit host authorization or capacity error is passed to the guest as a non-success authorization or insufficient-space result. Missing parents retain the archive's existing missing-path result; ambiguous host failures return a generic non-success FS result. For resize failures, known authorization/capacity failures are distinguished; other failures retain the existing excessive-size result. These host errno mappings use conventional result descriptions, not independently measured 3DS hardware responses to an emulator host fault.

Host permission and data ownership must still be fixed separately. This does not claim that an inaccessible save directory is now writable, move or erase user data, change archive formats, or bypass storage permissions.

The new `cara-guest-fs-host-failure-self-test` invokes actual `IOFile`, `SaveDataArchive::CreateFile`, `SDMCArchive::CreateFile`, and their open-create route. It uses a ROM-free temporary directory, native missing-parent/valid-file controls, and deterministic fault injection at the actual IO factory interface. The test covers zero and positive lengths, errno retention across move, authorization and full-disk rejection, unknown error rejection, denied resize, and successful exact-length file creation. Compile and run it with the existing host build configured for Cara self-tests.

Separate audit observation: `DiskFile::SetSize` and the corresponding service currently do not propagate their backend resize result. That is outside this create/open crash correction and needs a dedicated guest-semantic review, especially for read-only/extdata backends whose resize restrictions differ.
