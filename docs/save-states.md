# Save states

While a game is running, open **Menu → Save state** or **Menu → Load state** and choose one of ten slots. Saving replaces that slot. Loading discards progress since the checkpoint. In-game saves remain separate and should still be used.

States are compressed `.carastate` files in Cara's user-data `states` directory. Slots are separated by game title; homebrew without a title ID uses its executable hash. State files contain game memory and must not be committed to this repository.

A state restores the emulated ARM CPUs, timing events, RAM/VRAM, kernel objects, service state, PICA registers and shader programs, and HLE DSP state. Decoded interpreter blocks and host GPU caches are rebuilt. Operations run on the emulation thread between guest slices. They do not allocate executable memory or enable JIT.

State loading requires the same game executable, engine fingerprint, CPU backend, and 3DS system mode. The engine fingerprint includes engine source, compiler, architecture and pointer size. Generated build dates and branch metadata are excluded. Updates can invalidate states; regular game saves are the durable format. Multiplayer must be disconnected. States are local; the existing iCloud save-folder feature continues to sync game saves only.

The file envelope checks format, exact size, Zstandard frame size, SHA-256 checksum and compatibility before applying an archive. The current session is captured for rollback if deserialization fails. Writes use a temporary file and atomic replacement. Loading does not rewind files already written by a game's own save commands.

## Validation

`cara-save-state-self-test` uses an original ARM ELF generated by `tools/make_test_elf.py`. It checks CPU/RAM/timing restoration, VRAM and vertex-program restoration, deterministic continuation, repeated loads, incompatible/corrupt input rejection, and rollback after a late archive failure. It requires no commercial ROM or firmware.

`cara-save-archive-relocation-self-test` checks actual SaveData, SDMC, SDMC write-only,
SystemSaveData, extdata and shared-extdata archive/factory serializers, plus an open
`IOFile`. Run it through `python3 tests/save_archive_relocation_test.py EXE OUTPUT_DIR`
or CTest's `cara-save-archive-relocation` test. The runner creates authored files in
private directories, saves under root A and restores in a fresh process under B.
It tests both A still existing and A being absent, verifies all writes go to B,
and checks that A's original files and external-root sentinels remain unchanged.

Archive and factory host paths now use the same `%CARA_USER_DIR%` serialization
wrapper as open files. Previously, a restored open file could rebase to B while
its archive retained A: reopening a file could write the old tree or fail if it
was gone. This is reproduced with the ROM-free fixture. It does not establish
the cause of any particular game's missing save. Paths outside the current user
root retain the existing wrapper's behavior; old state archives are not searched
or rewritten to guess a replacement root. `SetUserPath` behavior is unchanged.

Serialization is restored from Citra MMJ revision `11b01c0a28e4441dc8902ea2ea88d9bcaf1efbc4`, immediately before MMJ removed it in `e85a43cf92e446b4ac4af99a22b53655ea12b92e`, and adapted for Cara's four-core scheduler, FastInterp, native file I/O and GLES renderer. Original Citra copyright and GPL notices are retained.
