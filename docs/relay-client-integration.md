# Relay client and UDS integration

The optional Apple relay transport and NWM service bridge are implemented. They use the deployed TLS WebSocket relay at `wss://carap2p.therad.ninja/relay`. Native transport and two-process service-HLE witnesses pass. These establish packet delivery and emulator service behavior, **not Pokémon trades/battles, guest-issued UDS IPC, Nintendo online services, or StreetPass exchange**. The companion iOS room controls and lifecycle hooks are reviewed separately.

## Frontend contract and lifecycle

`network/relay_client.h` is standard C++. `RelayClient::Create()` returns a shared host session. `Connect(Config{endpoint,room,password})` starts asynchronous admission; its return value does not mean connected. `GetStatus()` and fixed `StatusText()` expose bounded generic state without remote text or credentials. `Disconnect()` cancels tasks, invalidates the generation and clears queues. No callback owns a raw service/kernel pointer.

Install the shared session with `Network::InstallRelaySession` before `System::Load`. Keep it stable for that ROM. Invoke `Network::DrainRelayPackets(system)` immediately before normal foreground `RunLoop`. The empty/disconnected path reads an atomic wake flag and returns without registry locks, status queries or vector allocation. Work drains at most 32 FIFO events; remaining work rearms the flag. URLSession delegates only parse/validate/queue host values. HLE/kernel/memory operations occur on the emulation worker with the recursive HLE lock.

Background, ROM switch, state load and shutdown must disconnect before destroying services. First synchronization clears restored associations and cached peers/beacons even if the new constructor observed the same disconnected generation; it signals actual lost-association events and reasserts the current virtual MAC after Kernel shared-page restore. Sockets, room passwords, source IDs, reconnect tokens and host generations are never serialized. Foreground menus while online must keep ordinary paced guest execution running or explicitly disconnect; do not pump HLE separately while guest time is paused.

The Foundation session is ephemeral, uses system hostname trust with TLS minimum 1.3, rejects redirects, accepts only binary messages and limits them to 4,101B. URL user/password/query/fragment components are forbidden even when empty. Scheme comparison is case-insensitive. Room names are 1..64 UTF-8 bytes and passwords 1..512 bytes; server rooms still require configured high-entropy passwords. Credentials never enter URLs, logs or command arguments. There is no certificate bypass, ATS exception, automatic game-launch connection or persistence of credentials.

## Wire and membership

The shared `network/wifi_envelope.h` codec has version 1, kind 0..5, radio channel, zero reserved byte, transmitter/destination MAC 6 each, payload length u16 BE and exact payload. Its 18B header fits within the relay's 4,088B opaque limit. NodeMap uses fixed u16 BE counts and IDs with at most 16 entries; checked bridge helpers translate to/from the existing internal native NodeMap representation. Existing ENet serialization remains unchanged.

The client requires the relay's opt-in membership capability before becoming Connected. Server-assigned PeerJoined/PeerLeft IDs are authenticated by the same TLS room connection. Source→MAC bindings exist only for current admitted IDs. An active duplicate MAC or a peer changing its MAC fails closed. A server PeerLeft retires that binding and queues a control event on the same FIFO as packets, before any replacement can reach NWM. Unknown, never-bound departures do not fabricate a MAC.

A random 128-bit memory-only instance token lets the server retire an old connection before admitting its same-room replacement, even when socket cancellation races a new handshake. Tokens are not console/account identities and are never broadcast or logged. The server's global connection/handshake cap remains intact; full capacity may require an explicit retry. The opt-in protocol preserves the legacy Welcome/Packet stream for clients that do not request it.

## Admission and bounds

The pure state policy in `network/uds_relay_admission.h` runs again against the current NWM snapshot before callback. It checks destination/channel/self filtering, chosen-host authority, assigned source nodes, host capacity/storage and legal connection phase. Authentication/association/EAPoL frames cannot make an arbitrary room peer replace the chosen host or its NodeMap. SecureData's source node must belong to its transmitter; authoritative-host forwarding is an explicit exception limited to known assigned nodes. Host node 1 is absent from the existing synthetic NodeMap and is handled explicitly.

Connected peer departure uses the host's deauth cleanup; pending-auth departure simply releases its pending entry. A client disconnects only when its selected host leaves. Host deauth broadcasts the existing authoritative NodeMap, allowing a later-joined client to prune a departed peer it knew only through that map. Removed assignments also purge their queued data before node reuse. Active host NodeInfo entries stay compact while retaining node IDs; received Logoff records rebuild status arrays by actual node ID, including sparse/reused order `[1,3,2]`.

RX and TX each have 64-packet/256KiB caps; stream reassembly is bounded to 8,202B. Sends are serialized with only one Foundation send in flight. Slow/overflowing transport sessions disconnect and clear their generation. UDS separately caps each data channel to 64 packets and all channel backlog to 256KiB. Beacons remain capped at 15; mapped beacon replies count only complete entries that fit the actual guest output, including short-header rejection. All NWM outbound packets, including ordinary guest sends, beacons and callback replies, require the service's exact generation. The Apple transport checks it and enqueues under the same wire mutex; expected generation 0 is never a wildcard. No guest clock, instruction charge, timer visibility, event deadline or idle-loop policy changes.

## Reproducible evidence

`tools/network-relay/client-prototype/check.sh` compiles the same shared codec, stream/session parser and admission policy under ASan+UBSan with no extra libraries or network. Results:72,604 codec assertions and 100,000 deterministic mutations;250,000 standalone mutations/resizes;2,263 stream/membership/queue/generation assertions;290 state/host/node assertions. These are deterministic mutation checks, not coverage-guided fuzzing. The Apple toolchains lacked a libFuzzer runtime; its portable entry point is retained.

Apple CMake provides these explicit standalone targets:

- `cara-relay-client-configuration-self-test`: malformed/empty URL components, uppercase scheme, byte limits and cancellation generation.
- `cara-relay-client-live-test`: private stdin credentials; independent sender/receiver, exact maximum envelope and reply, source tag, no echo, isolated room and bad-password rejection.
- `cara-relay-client-reconnect-test`: two processes;40 same-MAC reconnect epochs, unique source IDs and trusted leave before every rebind.
- `cara-nwm-relay-hle-live-test` (headless software presentation only): actual Core/Kernel/NWM service-HLE witness. Generate its original guest with `tools/make_uds_test_elf.py`. Run `BINARY ELF EMPTY_OUTPUT_DIRECTORY --offline` for pending/full host, sparse node reuse, host authority, NodeMap-only departure, channel/global queues, real mapped beacon IPC buffer bounds, unchanged ticks and restored-association checks. Live mode instead reads private JSON config on stdin and uses two processes (`role` host/client).

The live NWM witness loads an original generated busy-counter ELF, initializes real UDS shared memory/events, discovers an actual beacon, and invokes actual Initialize/BeginHosting/Connect/Bind/SendTo/PullPacket helpers. It verifies 512-byte payloads both ways, assigned node 2, source spoof rejection, departure/status events and disconnected restore handling. It enters the generated guest before Connect so the requesting thread is Running. Host pacing retains 100% guest ticks through ordinary RunLoop. The test-only friend driver invokes services; the generated guest itself does not issue UDS IPC. No firmware or proprietary assets are needed. The standalone fixture has no production UI entry point.

Native syntax/compile and these receipts do not certify arbitrary game behavior. Next release proof is two real isolated game instances performing a named local-wireless action and preserving their saves; StreetPass and Internet-service integration remain separate work.

Primary API references: [Apple URLSessionWebSocketTask](https://developer.apple.com/documentation/foundation/urlsessionwebsockettask), [TLS minimum](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/tlsminimumsupportedprotocolversion). Local SDK declarations were also checked.

## Native Mac developer host and a real-game test

The native SDL frontend now supports explicit `--relay-stdin`. It reads one bounded JSON line from a pipe with `room`, `password` and optional `endpoint`; terminal input is refused to avoid echo. Unknown fields, invalid types, embedded NULs, malformed endpoints and oversized values are rejected with generic messages. No credentials enter arguments, environment, diagnostic output or native manifests. The default remains disconnected and adds no per-frame relay work. The same stable host session is installed before game load, receives only before the ordinary RunLoop, and disconnects before state restoration and teardown. The frontend runs one ROM per process; ROM switching means exiting it.

`tools/run_native_relay.py` retrieves an existing room over authenticated SSH into memory and passes it to the native process over stdin. Give each instance a distinct absolute `--user-dir`, an isolated copy of its in-game save and a compatible owned `--rom`; never point two processes at the same directory. This helper does not create rooms, copy saves, or alter the server. Its default room is the already-provisioned `cara-private`; access requires the existing administrative SSH account. The iOS UI needs that room's credentials entered privately by the user, obtained through their authenticated administrative channel. There is no public invite or self-service room creation.

For the first Pokémon proof, back up original saves, use isolated save copies with local multiplayer unlocked, match game/update versions, launch both instances and wait for generic `Connected` status, then use the game's local wireless screen. Record discovery, accepted invitation, a completed battle or trade, disconnect/rejoin and save integrity. Start with a battle to avoid changing Pokémon ownership during initial validation. An identical copied trainer save has not yet been tested; do not edit trainer IDs or assume they must differ without game evidence. Internet/PSS Internet mode, StreetPass and mere room connection are not substitutes for this proof. No named Pokémon action has been certified by the transport or HLE tests above.

The standalone `tests/native_relay_config_test.mm` checks private JSON and URL boundaries without a ROM, socket, game launch or credentials. Compile it with `native_mac/relay_config.mm`, Foundation and the emulator source include directory.

`tools/show_private_relay_room.py` is a user-operated Terminal handoff for entering the already-provisioned room on iPad. It refuses captured or redirected output, retrieves credentials over authenticated SSH into memory, reveals only after Enter, and clears its alternate terminal screen on exit or after two minutes. It does not create public invitations, URLs containing credentials, clipboard entries or credential files. Run it directly in your own Terminal; do not run it through assistant tool output.

With `CARA_NATIVE_DIAGNOSTICS=1` only, a dedicated native user directory accepts `touch X Y FRAMES` in `native-command.txt`. Coordinates address the guest bottom screen (X0–319, Y0–239), duration1–600 frames. The current bottom-screen framebuffer rectangle handles window scaling; hidden/empty touchscreens and malformed/extra/overlong commands are rejected. Touch releases at the requested frame or after30 seconds, on focus loss, window close and destruction. Commands are polled at the existing30-frame diagnostic boundary, without changing guest timing. The touch parser/mapping and private configuration self-tests are explicit CMake targets and macOS SDL CI steps with assertions enabled in Release.

For a fresh native multiplayer directory, pass `--initialize-gpu-config` once to `tools/run_native_relay.py`. This explicitly creates `[Renderer] use_hw_renderer=true` and `use_hw_shader=true` only if its native config is absent. The launcher refuses absent, malformed or software-renderer configurations before retrieving private credentials or launching the game; existing settings are never overwritten. This is a launcher test preset, not an engine-default change or proof that every game renders correctly. `tools/test_native_relay_runner.py` verifies creation and existing-setting preservation without a ROM or network.
