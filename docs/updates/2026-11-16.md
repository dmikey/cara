# November 16 development update

**Release preparation: validated development results and a local Mac gameplay build.**
No release version or new physical-device rollout is claimed by this document.

## What players should notice

Luigi’s Mansion: Dark Moon reached near-full speed in the tested M1 Mac scene
without reducing the guest CPU clock, removing effects or enabling JIT. Keeping a
recurring graphics-memory conversion on the GPU brought completed-work frame time
from **28.41 to 16.65 ms**, a **41.4% reduction**, near the existing 60 Hz cap.

The same development path passed a populated-cache save/load replay and Zelda’s
normal-boot opener checks. These are bounded scene and correctness results;
longer gameplay and other titles remain separate validation targets.

Recent changes already merged into `main` also improve native index scanning and
fix archive paths when a compatible save state is restored under a relocated
user-data directory. Regular in-game saves remain the durable progress format;
save states still require a compatible engine build and game executable.

## What changed in the renderer

Luigi repeatedly viewed a tiled RGBA8 render-target backing through a linear
texture layout. The native path had not admitted this case, so validation fell
back to downloading pixels and uploading them again. Enabling the existing GPU
RGBA8 remapper keeps the eligible conversion resident while preserving guest byte
addressing. Unsupported formats/layouts still use the existing fallback.

This builds on Cara’s earlier physical M4 GLES byte-remapping work; it is not a
Metal migration, a title-ID special case or a new 60 FPS patch.

One same-binary OFF/ON/ON/OFF comparison on the M1 measured 120 refreshes per arm:

| Arm | Completed-work ms/refresh | Producer readbacks |
| --- | ---: | ---: |
| Off A1 | 28.254 | 240 |
| On B1 | 16.650 | 0 |
| On B2 | 16.651 | 0 |
| Off A2 | 28.569 | 240 |

Both enabled runs were faster than both controls. The means are 28.412 and
16.651 ms, saving 11.761 ms per refresh. All arms retained FastInterp, 100% guest
CPU, cap100, sound, normal graphics checks, effects and guest timing. The
unchecked-copy recorder was disabled. Final RGBA, both LCD images, selected
architectural state and persistent files matched. The cap prevents an uncapped
throughput claim; this is one ABBA in one scene, not universal full-speed proof.

The [performance page](../performance.md) gives measurement constraints. The
[sanitized evidence summary](../evidence/m1-native-rgba8-2026-11-16.json) records
exact values and build/report identities; private game assets remain outside Git.

## Correctness and compatibility

- **Luigi runtime save/load:** saved after active remap-enabled rendering,
  advanced the game, loaded in the same process, then compared against a fresh
  process loading that exact compatible archive. Five image/LCD checkpoints,
  selected CPU/VFP/CPSR/timer/HID state, metadata, guest files and queue-epoch
  transitions passed. This is not byte-for-byte proof of every VRAM location.
- **Zelda opener:** native-remap off/on matched six normal-boot checkpoints,
  selected state and guest files, including earlier opener reference images.
  This was an opener regression check, not a performance or full-game result.
- **Stories current scene:** off/on output, selected state and files matched.
  Both arms already had zero producer readbacks. Enabling the flag added 1,200
  synchronous host transactions over 120 refreshes; its performance effect was
  not quietly measured. No Stories gain is attributed to this remap result.

## Local Mac gameplay build

The separately packaged Cara FastInterp app built successfully and loaded Luigi
in ordinary play mode. Runtime settings confirm all guest CPU timers at 100%,
SDL sound, no CPU/shader JIT, normal graphics checks, the ordered mapped-upload
path and native RGBA8 remap enabled. Diagnostics, benchmark exit controls,
automatic test input and developer command polling are disabled.

File → Open… / ⌘O uses a native ROM picker and a clean session shutdown/relaunch
path, retaining the app’s persistent save folder. The native action fixture
passed cancel and single-switch handoff checks. Actual live UI-driven switching
was not automated; longer gameplay and user-driven switching remain acceptance
work. This installed development binary is distinct from both the timed b097
binary and current GitHub main. It is not a published release or an iPad update.

### Mac presentation stall: unresolved stability issue

A later ordinary-play stall was captured as a host-thread dependency cycle:
the producer waited for render-queue space while the render worker’s SDL buffer
swap waited for a main-thread context update. The launcher now sets
`SDL_MAC_OPENGL_ASYNC_DISPATCH=1`, the
[SDL2 setting for this worker/main-thread context-update dependency](https://wiki.libsdl.org/SDL2/SDL_HINT_MAC_OPENGL_ASYNC_DISPATCH).
The attempted recovery changes the launch environment, not the emulator binary
or guest timing. The app reopened with the setting active and subsequent samples
showed both threads working, but a later freeze was reported. The first setting
change is therefore not a complete stability fix; the recurring stall remains
under investigation. This is separate from the matched checkpoint speed result
and must be resolved before claiming stable longer gameplay.

## Other recent fixes already in main

### Native index bounds

[PR #5](https://github.com/dmikey/cara/pull/5), merged as `4c41524`, keeps live
8/16-bit index reductions at source width and widens only the final bounds.
It avoids unnecessary conversion work without caching mutable guest memory.
The maintained regression covers 77,926 cases, live mutations and guarded pages;
GitHub builds and runs it. Large-array scan-only gains do not establish a gameplay
speedup, and tiny-count results are mixed. [Details](../native-index-range-m1-20261114.md)

### Relocated save archive paths

[PR #4](https://github.com/dmikey/cara/pull/4) makes archive/factory paths use the
same user-root serialization wrapper as open files. Previously an open file could
rebase to a new data directory while its archive still pointed at the old root.
ROM-free fresh-process tests cover both the old directory remaining and being
absent, writes reaching the new directory and preserved external sentinels.
This does not make old engine-specific states universally compatible or establish
the cause of any particular missing game save. [Details](../save-states.md)

## Research results kept separate from release claims

The corrected mapped-upload worker prototype reduced completed-work time by
6.3–6.4% in repeated Stories comparisons and 4.1–7.5% in Luigi comparisons.
Whole-process CPU increased. These results belong to that prototype/build;
they are not added to the later Luigi remap percentage. The earlier SubData
adapter regression is not used as the performance baseline.

A separate unchecked-recorder diagnostic showed a 5.43 ms Stories gap and a
1.62 ms Luigi gap, but changed both transport and check policy. It is not a
checks-preserving production speedup, and disabling checks is not the release
plan. Shared-memory GL→Metal→GL copy tests were slower than GL-only at every
sampled size; synthetic large-batch Metal index expansion is not Cara gameplay
proof. Neither experiment justifies claiming a new native graphics backend.

Stories’ retained traces show approximately 200 Hz update pacing, with graphics
work scaling with update frequency. P3D wakes a descriptor worker; its outstanding
work gate and main-thread synchronization are distinct from the high-level render
worker’s completion event. Next-batch building overlaps older descriptor dispatch.
The exact hardware latency and runtime admission-window behavior remain unproved.
We have not fixed this by capping all graphics preparation to 60 Hz or changing
guest timing. [Causal findings](../gpu-frame-production.md#retained-m1-causal-traces-2026-11-15)
